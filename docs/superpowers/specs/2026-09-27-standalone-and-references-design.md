## 1. Purpose

Skills reach a machine today by three routes. The two plugins carry seven first-party, vendored and forked skills, an agent and a hook; two subset entries carry obra/superpowers' thirteen and softaworks' `writing-clearly-and-concisely` on Claude Code; and `bin/setup`, 1,126 lines, installs nineteen more through skills.sh and gives Codex the subset entries' skills through a pinned clone and symlinks in `~/.agents/skills`. Installing `sensemaking` alone gives two skills. One shipped skill names a plugin this marketplace does not have, and the check that exists to catch that sees three hardcoded prefixes. Two tests hold copied descriptions to 122 characters, one catalogue's share of Codex's budget, not a limit. The premise under the symlinks, that Codex cannot take part of an upstream, is false on codex-cli 0.147.0 (§6), and Codex parity needs no copy of a Claude-only plugin's skill: Codex installs a Claude-format plugin as it stands (measured 2026-09-30; §21).

After this branch:

- every skill a plugin offers ships inside it, as first-party, as a copy a drift test holds to upstream, or as a fork; only superpowers, the one subset entry, comes from upstream at install (§5, §6);
- one marketplace file serves both agent CLIs, and each installs the plugins with its own commands, which the README carries; `bin/setup`, `bin/doctor`, skills.sh and `skills.json` go; of the three skills.sh installs no plugin takes, `archify` and `developing-claude-code-plugins` stay installed as the user's own and the cleanup removes `working-with-claude-code` (§5.3, §13);
- `sensemaking` installs on its own on both agent CLIs with all its skills;
- every qualified skill reference in shipped text resolves to something an install delivers, or a test fails naming it (§10);
- the suite holds only upstream drift and installability, beside the linters, the reference scan and the watch's and runner's tests (§15), and a CI job installs the plugins with the README's own commands on the newest stable agent CLIs (§14);
- every pin the watch reports as drifted is current, so the watch closes #60 (§9, §12).

One branch, because the issues share their files: the marketplace manifest, `vendored.json`, the drift tests, `tests/test-plugin-skills.sh`, the `brainstorming` copy, the watch and the READMEs.

## 5. What each plugin carries, and what goes

A plugin's `skills/` folder is its whole skill set on both agent CLIs: nothing a plugin offers arrives from outside it, and only superpowers arrives beside the plugins, through the one subset entry (§6). Each skill is held one of three ways. **First-party** is written here. A **copy** is upstream's bytes and file modes at a pinned commit, apart from its declared changes, held there by a drift test; it is what `CONTEXT.md` calls _vendored_ (§7). A **fork** is first-party and began as a copy; nothing holds it to upstream, and the watch reports its upstream for changes worth porting (§8). Each skill sits one level deep, `plugins/<p>/skills/<name>/`, since the pinned Codex validator and `tests/test-plugin-skills.sh` read one level and Claude Code's default scan does not recurse (measured; §21 declines the nested layout).

Placement follows the prose rule in `plugins/sensemaking/README.md`: a skill belongs to `sensemaking` when it is shared by more than one product or is not about software development, and to `software-dev` only when both are false. The mattpocock pin is the tag `v1.2.3`, commit `6acc160e4e0cd062dbbbd7a1b26ae92855edf07e`; the others are in §7.2.

## 7. Copies, records and drift tests

### 7.1 A copy and its declared changes

A copy is upstream's bytes and file modes at the pin, except its declared changes. Each declared change is a row of one array in its repository's drift test, with its reason, since every local change to a third-party skill needs a stated reason, and being new is not one. Two rules hold every declared change without holding its wording:

- **Each declared line still differs from upstream's.** A whole-tree copy that reverts a declared change then fails, instead of passing under an exemption that exempts nothing: with its description literal removed, `tests/test-vendored-brainstorming.sh` stayed green on a reverted line 3 (measured 2026-09-27).
- **Each declared line's upstream side is present exactly once upstream.** When upstream fixes or drops it, the test fails loudly and the change is retired in one commit, never silently reverted or silently kept. A declared addition, a line or file upstream lacks, must still be absent upstream.

A row gives the file's path, a kind, an anchor and the reason (T25):

- **`line`:** the anchor is upstream's whole line as a fixed string, present exactly once in upstream's file; the local file's line at the same position, counted after `added` lines are removed, differs; and the two files are equal with that line removed from both. The two descriptions are this kind.
- **`token`:** the anchor is a pattern, such as `[a-z-]+:writing-clearly-and-concisely` or `/setup-[a-z-]+`; upstream's file matches it exactly once, the local match differs, and both sides reduce the match to one placeholder before the diff. The pointer and Q41's two repoints are this kind.
- **`added`:** the anchor is a line or a file absent upstream, which must still be absent there, and it is removed from the local side before the diff. `adhd`'s frontmatter line and its Codex policy file are this kind.

Every drift test:

1. **Fetches the pin** with `fetch_pinned` in `tests/lib.sh`, which gains the assertion that the checkout's HEAD equals the pin, so an annotated tag object's sha fails for every caller; `tests/test-upstream-pin.sh`'s own HEAD check moves into it.
2. **Peels a tag record's tag to its sha**, through `refs/tags/<ref>^{}` and the bare tag for a lightweight one (Q66). `fetch_pinned` rejects a tag object but accepts a stale commit: a bump that moves `ref` and not `sha` would pass the drift test against the old commit while the watch, reading `ref`, reports clean.
3. **Compares each `trees` pair** with upstream at the pin: the file set, every file's bytes and every file's mode, except the declared changes. Modes are read from git's index here and from the tree at the pin, since `diff -r` compares none (Q66); `brainstorming`'s `plugins/software-dev/skills/brainstorming/scripts/start-server.sh`, which `visual-companion.md` runs directly, is the case that needs it.
4. **Holds each declared change** by §7.1's two rules, and asserts nothing about its wording.
5. **Keeps the complement**, where its repository has one (Q66, T27): the basenames of the directories that hold a `SKILL.md` at the pin, a duplicate basename itself a failure, equal the basenames of the record's `trees` and `forks` values together with the declared exclusions, each exclusion with one comment giving its reason. The three sets are disjoint, and an exclusion upstream no longer has fails. A new upstream skill is then a decision at the next bump rather than a silent omission. ## 11. Descriptions (#49)

### 11.1 The mechanism

Codex gives the skill catalogue 2% of the model's context window, counted in approximate tokens of four bytes; 8,000 characters only when the window is unknown. When every full line fits, nothing is shortened. When not, each entry's name and path are paid first and the rest is shared round-robin, one character per skill per pass, so the cut is the same for every long description to within one token and moves with the size of the user's catalogue: 118 to 120 characters at 119 entries in one scratch catalogue, 136 to 140 at the same count with shorter names. Any description longer than 1,024 characters is cut there with `...`. A skill whose Codex policy file sets `allow_implicit_invocation: false` is not in the model's catalogue at all. The allocator is byte-identical at rust-v0.147.0 and rust-v0.157.1; 0.157.1 adds `skills.max_context_tokens` and drops the warning that descriptions were shortened.

Claude Code caps each entry at 1,536 characters, gives the listing 1% of the window, drops whole descriptions on overflow, and keeps a `disable-model-invocation: true` skill's description out of context. So 122 is not a limit on either agent CLI, and the one length three independent sources agree on is 1,024: the Agent Skills specification, Anthropic's authoring guidance, and Codex's hard cap. No validator enforces it; `claude plugin validate --strict` passed an 1,118-character description. Every copied mattpocock description is between 51 and 313 characters (measured at `v1.2.3`).
