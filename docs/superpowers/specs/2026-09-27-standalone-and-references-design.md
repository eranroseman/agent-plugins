## 1. Purpose

Installing `sensemaking` alone on Claude Code gives two skills. The shared skills that make it worth installing arrive only through `bin/setup`'s skills.sh pass. One shipped skill names a plugin this marketplace does not have, and the check that exists to catch that sees three hardcoded prefixes and nothing else. Two tests hold vendored descriptions to 122 characters, a number that is one catalogue's share of Codex's budget, not a limit.

After this branch: `sensemaking` and `software-dev` each install their mattpocock skills with them on Claude Code; every qualified skill reference in shipped text resolves to something an install delivers, or a test fails naming it; the suite holds only what users and agent CLIs depend on (§15); no third-party skill carries a local change without a stated reason, except the regions #23's undo reverts (§12.2); and every pin the watch reports as drifted is current. The watch is `scripts/upstream-watch`, which `.github/workflows/upstream-watch.yml` runs daily and which files the drift issue.

One branch, because the issues share their files: the marketplace manifest, `skills.json`, `tests/test-plugin-skills.sh`, the vendored `brainstorming` file and its drift test, and the watch.

## 5. The offline watch test and the broken pipe (#69)

The watch's Codex section fetches `protocol.rs` from openai/codex and reads the first entry of its `DISCOVERABLE_PLUGIN_MANIFEST_PATHS` into `first_manifest` by piping `printf` into `awk`. `protocol.rs` is larger than the pipe buffer. With SIGPIPE at its default, `printf` dies silently and the substitution returns 141; with SIGPIPE ignored, as #60's body shows it is on the runner, `printf` writes _write error: Broken pipe_ to stderr, which the workflow's `2>&1` puts into every drift issue (both reproduced). The fix reads it with `awk … <<<"$protocol"`, so `printf` has no pipe to lose, and the comment above the neighbouring `case` check gains one sentence saying that check reads through a here-string for the same reason.

The section's _still first_ line reports whether `.codex-plugin/plugin.json` is still that list's first entry. Every subset entry's Codex prefix rests on it (§6, §9.2).

The test runs the whole watch offline, not by a new mode: a mode fed by the test's own `printf` would stay green if the call site went back to the pipe. It is a new file, `test-upstream-watch.sh`, rather than part of `tests/test-workflows.sh`, whose `# needs: actionlint shellcheck` would skip it on a machine without them. PATH stubs stand in for the network:

- a `git` whose one output line, a stable tag such as `<sha>\trefs/tags/v1.0.0`, answers every `ls-remote`; a branch-shaped line would make the watch die on the newest-tag lookup before the Codex section;
- a `curl` that serves a `loader.rs` line and a `protocol.rs` over 64 KiB with the match near the top.

The watch runs under `trap '' PIPE`, without which the test is green at HEAD. The test asserts an empty stderr and the _still first_ line. §9.5 and §14.2 add cases.

### 7.2 The scan

`tests/test-plugin-skills.sh` stops reading three hardcoded prefixes from `SKILL.md` files only.

- **Files:** `git ls-files` over `plugins/*/skills/**/*.md`, `plugins/*/agents/*.md`, `plugins/*/hooks/*.md` and `plugins/*/skills/*/agents/openai.yaml`, 25 files at `093a91c`. Not `checked()`, which drops every tree with a drift test, `brainstorming` and the hook file among them. Not READMEs: the software-dev README names the retired `superpowers:brainstorming` on purpose.
- **Tokens:** every `[a-z][a-z0-9-]*:[a-z][a-z0-9-]*`, with its file and line; 15 distinct at `093a91c`.
- **Shapes first:** a token preceded by `/` is the tail of the house `owner/repo:path` form, and one preceded by `//` is a URL authority; both are skipped, as `tests/test-links-resolve.sh` classifies them by shape.
- **Prefixes:** a reference `<p>:<s>` resolves only when `<p>` names a marketplace entry, or a plugin in `recommended.json` (§7.3), that delivers `<s>`; any other prefix fails. For a marketplace entry whose `source` is a string, a local plugin, that directory must ship `skills/<s>/SKILL.md` or `agents/<s>.md`. For a `git-subdir` entry, `<s>` must be the last segment of one of its `skills` paths, taken with `split("/") | last`, not a `basename` pipe, which drew a false SIGPIPE failure under `pipefail` in scratch. Any other source kind fails. A recommended plugin resolves when it lists the skill, so the scan and the doctor read one list.
- **Exceptions** for the idioms left, in the test, one comment each: `file:line`, `bug:triage`, `wayfinder:map`, and the three inline CSS tokens in `visual-companion.md`, re-measured by the plan. An exception whose prefix is a marketplace entry or a recommended plugin fails, so a dead reference with a known prefix can never be exempted; an exception matching no token fails, so the list cannot rot.
- **A permanent negative fixture:** the scan runs once more over a scratch copy with `nosuch:thing` and `software-dev:no-such-skill` injected, and both must fail by file, line and token.
- **`tests/test-hook.sh`'s qualified-name check on `working-rules.md` goes:** the scan covers that file and `using-superpowers.md`, which it never did.
- **The summary line** counts files scanned, references resolved and exceptions used, so a zero shows. The test's header comment, which says it checks `SKILL.md` files, follows, and so does `tests/test-hook.sh`'s.
- **Frontmatter `name`** equals the directory for every local skill and the file stem for every local agent, through one helper in `tests/lib.sh` that the subset tests call at their pins too (§6, §9.4), since both agent CLIs dispatch by `name`. This replaces the inspector's `name:` literal.
- **A bare agent name:** a backticked span equal to a local agent's name fails, since the Agent tool accepts only `<plugin>:<name>` (measured 2026-09-06). This replaces the inspector's one-agent ban.

Red first: the scan goes red on the old pointer before §7.1's substitution turns it green. Landing the scan before the substitution, with `elements-of-style` excepted, would rebuild the defect.

## 12. Descriptions (#49)

### 12.1 The mechanism

Codex gives the skill catalogue 2% of the model's context window, counted in approximate tokens of four bytes; 8,000 characters only when the window is unknown. When every full line fits, nothing is shortened. When not, each entry's name and path are paid first and the rest is shared round-robin, one character per skill per pass, so the cut is the same for every long description to within one token and moves with the size of the user's catalogue: 118 to 120 characters at 119 entries in one scratch catalogue, 136 to 140 at the same count with shorter names. Any description longer than 1,024 characters is cut there with `...`. A skill whose Codex policy file sets `allow_implicit_invocation: false` is not in the model's catalogue at all. The allocator is byte-identical at rust-v0.147.0 and rust-v0.157.1; 0.157.1 adds `skills.max_context_tokens` and drops the warning that descriptions were shortened.

Claude Code caps each entry at 1,536 characters, gives the listing 1% of the window, drops whole descriptions on overflow, and keeps a `disable-model-invocation: true` skill's description out of context. So 122 is not a limit on either agent CLI, and the one length three independent sources agree on is 1,024: the Agent Skills specification, Anthropic's authoring guidance, and Codex's hard cap. No validator enforces it; `claude plugin validate --strict` passed an 1,118-character description.

## 15. What the suite holds

The maintainer's rule of 2026-09-27: a test holds one of two things, that nothing drifts from a third-party upstream, and that the plugins install. ### 18.2 The Ubuntu 26 pre-check (#70)

GitHub moves `ubuntu-latest` to Ubuntu 26.04 over several weeks from 2026-10-19, finishing by 2026-11-19, and the image is already generally available (actions/runner-images#14748). What can move with the image is what the suite takes from it rather than pinning: bash, `jq`, `git`, `curl`, GNU `date` and `find`, and npm's global install location. The tools in `tests/tools.txt`, and the runtimes setup-node and setup-python install, do not.

The two run ids, three jobs between them, and any new annotation are recorded, and the throwaway branch is deleted; nothing from it merges, and `ubuntu-latest` stays, for the reasons of names-and-surface §14.

A failure blocks the merge. A small one is fixed on the branch, and a gate-time fix under `plugins/` moves the version bump after it; one that is not small is filed, and the maintainer decides whether the merge waits.
