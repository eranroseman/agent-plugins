## 1. Purpose

Skills reach a machine today by three routes. The two plugins carry seven first-party, vendored and forked skills, an agent and a hook; two subset entries carry obra/superpowers' thirteen and softaworks' `writing-clearly-and-concisely` on Claude Code; and `bin/setup`, 1,126 lines, installs nineteen more through skills.sh and gives Codex the subset entries' skills through a pinned clone and symlinks in `~/.agents/skills`. Installing `sensemaking` alone gives two skills. One shipped skill names a plugin this marketplace does not have, and the check that exists to catch that sees three hardcoded prefixes. Two tests hold copied descriptions to 122 characters, one catalogue's share of Codex's budget, not a limit. The premise under the symlinks, that Codex cannot take part of an upstream, is false on codex-cli 0.147.0: Codex installs a subset entry from the Claude marketplace file, loads only its listed skills and names them by the entry (§6), and it installs a Claude-format plugin as it stands (measured 2026-09-28 and 2026-09-30; §21). So a skill this repository does not change needs no copy, and the skills `sensemaking` was made to share between software development and research-vault can arrive through subset entries instead. Superpowers needs no entry here at all: obra's own marketplace serves it to each agent CLI (§6.1).

After this branch:

- `software-dev` is the one plugin (Q70, Q74). It carries what this repository writes or changes: first-party skills, two copies a test holds to upstream, `diagnosing-bugs` and `adhd`, and two forks, `setup-matt-pocock-skills` and `finding-duplicate-functions`. Every other third-party skill taken as-is comes from one of two subset entries, `mattpocock` and `elements-of-style`, which `software-dev` depends on (Q71, Q73, Q79; §5, §6). Superpowers comes from obra's own marketplace, which the README's blocks install on each agent CLI (Q78, Q87; §6.1, §13.2). `sensemaking` retires, and its two skills move into `software-dev` (§5.2);
- one marketplace file serves both agent CLIs, and each installs with its own commands, which the README carries: one `claude plugin install software-dev@eranroseman` plus obra's two lines on Claude Code, and one block adding each of the three by name plus obra's two lines on Codex; `bin/setup`, `bin/doctor`, skills.sh and `skills.json` go; of the three skills.sh installs neither the plugin nor an entry takes, `archify` and `developing-claude-code-plugins` stay installed as the user's own and the cleanup removes `working-with-claude-code` (§5.3, §13);
- every qualified skill reference in shipped text resolves to something an install delivers, or a test fails naming it, the install job for a `superpowers:` reference (§10, §14);
- the suite holds only upstream drift and installability, beside the linters, the reference scan and the watch's and runner's tests (§15), and a CI job installs the plugin, its entries and obra's superpowers with the README's own commands on the newest stable agent CLIs, and checks every `superpowers:` reference against the superpowers it installs (§14);
- every pin the watch reports is current at the merge, so the watch closes #60 (§9, §12).

One branch, because the issues share their files: the marketplace manifest, `vendored.json`, the drift tests, `tests/test-plugin-skills.sh`, the watch and the READMEs.

## 7. Copies, records and the upstream test

### 7.1 A copy and its declared changes

A copy is upstream's bytes and file modes at the pin, except its declared changes. Each declared change is a row of one array in `test-upstream.sh` (T45), with its reason, since every local change to a third-party skill needs a stated reason, and being new is not one. Two rules hold every declared change without holding its wording:

- **Each declared line still differs from upstream's.** A whole-tree copy that reverts a declared change then fails, instead of passing under an exemption that exempts nothing: with its description literal removed, `tests/test-vendored-brainstorming.sh` stayed green on a reverted line 3 (measured 2026-09-27).
- **Each declared line's upstream side is present exactly once upstream.** When upstream fixes or drops it, the test fails loudly and the change is retired in one commit, never silently reverted or silently kept. A declared addition, a line or file upstream lacks, must still be absent upstream.

A row gives the file's path, a kind, an anchor and the reason (T25, T46):

- **`line`:** the anchor is upstream's whole line as a fixed string, present exactly once in upstream's file; the local file's line at the same position, counted after `added` lines are removed, differs; and the two files are equal with that line removed from both. `diagnosing-bugs`' description is this kind.
- **`added`:** the anchor is a line or a file absent upstream, which must still be absent there, and it is removed from the local side before the diff. `adhd`'s frontmatter line and its Codex policy file are this kind.

## 11. Descriptions (#49)

### 11.1 The mechanism

Codex gives the skill catalogue 2% of the model's context window, counted in approximate tokens of four bytes; 8,000 characters only when the window is unknown. When every full line fits, nothing is shortened. When not, each entry's name and path are paid first and the rest is shared round-robin, one character per skill per pass, so the cut is the same for every long description to within one token and moves with the size of the user's catalogue: 118 to 120 characters at 119 entries in one scratch catalogue, 136 to 140 at the same count with shorter names. Any description longer than 1,024 characters is cut there with `...`. A skill whose Codex policy file sets `allow_implicit_invocation: false` is not in the model's catalogue at all. The allocator is byte-identical at rust-v0.147.0 and rust-v0.157.1; 0.157.1 adds `skills.max_context_tokens` and drops the warning that descriptions were shortened.

Claude Code caps each entry at 1,536 characters, gives the listing 1% of the window, drops whole descriptions on overflow, and keeps a `disable-model-invocation: true` skill's description out of context. So 122 is not a limit on either agent CLI, and the one length three independent sources agree on is 1,024: the Agent Skills specification, Anthropic's authoring guidance, and Codex's hard cap. No validator enforces it; `claude plugin validate --strict` passed an 1,118-character description. Every description of the sixteen mattpocock skills is between 51 and 313 characters (measured at `v1.2.3`).

## 15. What the suite holds

### 15.1 The rule

The maintainer's rule of 2026-09-27: a test holds one of two things, that nothing drifts from a third-party upstream, and that the plugins install. Beside them stay the linters (lint, format, spelling, vocabulary, the reference check on documents, the workflow lint), the skill-reference scan (§10.2), the watch's tests (§12.4) and the runner's tests. Nothing else: no check holds this repository's own wording, literals, counts or headers, since such a check keeps content alive only because the check exists, and every deliberate change then needs a second edit to satisfy it. It lives in this spec only (Q20, §4).

Under the rule this spec plans no description table (#33 declined), no placement-table test (#55, the table itself deleted), no ban on `if available` or on bare skill names (§10.2 bans only a bare agent name, which the Agent tool cannot dispatch), no guard holding `rethink-audit`, no test holding a fork's content, and no static check of the marketplace's name, a literal of our own that the install job's README blocks already exercise. What today's tests hold beyond the rule goes, or becomes the property it stood for. The list comes from the audit of every assertion in the suite on 2026-09-27, each finding challenged by a second agent, and from the two test audits of 2026-09-29.
